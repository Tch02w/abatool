# 完整结果批量任务（F012）

本功能按目标的唯一祖先路径生成完整 ODB。计算依赖仍由重启动链维护，结果图只组织已有 ODB，不启动求解。手工两文件合并及每一步的内容校验见 [安全合并](ODB_MERGE.md)。

从重启动队列发起时，预览与批量执行前的重新核对都使用当前后台的队列文件；独立结果图仍使用其自己的图存储。指定独立队列的后台不会借用默认队列来补全或替换祖先。请求和检查点格式不变，计划变更、目标缺失、失败与取消继续按原规则处理。

## 操作

1. 在 ODB 合并页编辑并保存独立结果图，选择目标并检查计划；也可从重启动链使用「生成此节点完整结果」。多个前置作业或同名前置无法唯一确定时，先修正依赖。
2. 选择历史输出、压缩与复制选项，执行合并。整批使用提交时的选项快照。输出统一自动编号，避免覆盖源文件或旧结果。
3. 页面显示完成目标数和独立合并阶段数。共享祖先只执行一次；兄弟分支各自使用该祖先结果，不互相合并。自动编号后的实际输出会传给后续步骤。
4. 切换页面不会终止后台执行。重新进入或点击「读取后台任务」恢复状态。网络错误或开始请求未收到回复时先读取任务，不重复点击执行。
5. 后台重启后，未结束批次显示等待继续。点击「检查并继续批量任务」后先检查来源和已完成结果，再接续尚未提交的阶段。此操作使用原批次选项，不能通过修改当前草稿改变旧批次。

## 保存与恢复

最新源码为结果图的未保存编辑增加独立检查点，纳入每两秒的工作台草稿保存。JSON路径为 `%LOCALAPPDATA%/AbaqusTools/result-graph-draft.json`，保存正式基线、当前节点/路径原文、输出目录、当前节点与勾选目标；不复制ODB，不提交正式图，不启动合并。最多256节点、文件4MiB；超过上限或保存失败保留旧检查点并显示原因。

重开后先读取正式图。「发现未保存的结果图」中，基线相同可点「恢复编辑」，随后核对并点击原「保存」。恢复后仍是未保存状态，后台继续检查版本冲突。正式版本、内容或运行环境不同则禁止直接恢复；可点「查看草稿」选取复制内容，或「保留副本并忽略」继续使用正式图。损坏草稿不会被自动覆盖。副本命名为原文件名加`.preserved-时间-唯一编号.json`，先完整写入并flush，再清除活动检查点；保留失败则不清除。主动重新读取并确认放弃编辑也先保留副本，期间暂停定期捕获，避免重建已放弃草稿。

此处恢复仅针对编辑元数据，与下方批量执行恢复不同。原生按钮/键盘/重开流程待验，现有完整安装候选尚未包含新源码；详见[ADR0018](../submitter/adr/0018-result-graph-recovery-drafts.md)。

descriptor 同目录的 `odb-result-batches.sqlite3` 保存请求身份、不可变计划、合并选项、各阶段提交记录、子任务标识及已验证结果摘要。实际单步合并记录保存在 `odb-merge-history.sqlite3`。两者均需保留，不应单独移动、删除或覆盖。

每个阶段使用固定请求标识。即使后台在单步成功后、批量进度保存前退出，也会查找原单步记录并验证文件，而不是重跑。若已提交阶段的子任务记录缺失，或原子任务显示“中断待核对”，整批停止接续。此时核实原进程、目标目录和校验回执；不能只凭文件存在判定成功。程序不自动清理不明现场或再次执行该阶段。

来源检查使用文件标识、大小、时间及首部/中部/尾部各最多 64 KiB 抽样 SHA256；这不是来源全文件摘要。每个已完成的中间 ODB 与内容校验回执另保存**全文件 SHA256**，恢复复用前完整重读并比较。复用校验会增加磁盘读取时间。生产执行期间应避免其他程序改写来源或中间结果；每步执行还保留 F013 的独立源保护和内容校验。

检查点只在准入、阶段提交、阶段完成及任务状态改变时保存，轮询不写数据库。文件锁确保同一历史只有一个写入者，未取得锁则拒绝新任务。

## 错误、停止与边界

- 任何阶段失败时不启动后续阶段，保留已经完成的目标和中间结果。源或结果摘要不一致不视为成功，不能补零或直接跳过。
- 「停止」禁止后续阶段并请求取消当前子任务，等实际子任务完成清理后结束批次。已发布文件不会被取消请求删除；若停止发生在结果摘要计算阶段，该文件仍可通过子任务记录核对，尚未列为完成目标。
- 记录无法保存时停止推进并禁止新任务。退出预留同时检查批量、单步合并、升级及本机/后处理/索引/远端等受管工作，即使两步之间没有外部进程也不会错误关闭后台。
- 来源中无结果帧的分析步提示保留在批量完成消息中。生成完整结果不表示原求解已完成。
- 失败/取消批次不能直接点击继续；保存现有结果，核对问题后重新生成计划。后台重启暂停的批次才提供继续入口。
- 恢复功能有隔离测试进程真实退出、HTTP 和客户端契约检查。11 月 18 日正式 C# HTTP 客户端通过冻结后台完成 GJB-15 两个真实兄弟目标，重启后相同批次和子任务恢复，输出完整摘要不变：V20D 8 步/70 帧，U100D 12 步/63 帧（保留 4 个无结果帧步骤提示），均包含历史输出。来源副本完整摘要未变，中文含空格输出路径通过。证据 `GPTWork/real-result-batch-750883913dd9/verification.json`；三层连续链、原生点击/布局仍待验收。
- 冻结后台突然退出、外部测试子进程仍存活的情况也已单独验证：重启后批次为等待继续，原单步为 `ODB_MERGE_INTERRUPTED`；尝试继续明确失败，不重放原阶段、不启动后续阶段、不发布结果。第三次启动仍恢复同一失败批次。验收工具 `packaging/verify_batch_interruption.py` 只使用微小非 ODB 夹具，不能代替真实 Abaqus 崩溃或工程连续三层链验收。回执 `GPTWork/frozen-batch-interruption-691d9fb533f3/verification.json`，所有自有测试进程已结束。

## 维护入口

- `modules/control_plane/odb_result_batches.py` / `OdbResultBatchManager`：计划准入、阶段去重、执行、停止与恢复。
- `modules/control_plane/operation_journal.py` / `OperationJournal`：共享 SQLite 存储，F013 仍沿用原表和版本。
- `modules/control_plane/restart_result_plans.py`：唯一祖先校验；结果图由 `modules/control_plane/odb_result_graphs.py` 提供。
- `winui/AbaqusTools.WinUI/Services/ControlPlaneHost.ResultBatch.cs`、`winui/AbaqusTools.WinUI/Services/OdbResultBatchContracts.cs`：批量请求和状态校验。
- `winui/AbaqusTools.WinUI/Pages/OdbMergePage.ResultGraph.cs`：创建、读取、继续与结果显示。
- `tests/control_plane/test_odb_result_batches.py`、`tests/control_plane/test_restart_result_plans_api.py`、`tests/winui_host/Program.cs`：恢复、拒绝重跑、数据变化、分支、取消、损坏和界面契约。

旧 `winui/AbaqusTools.WinUI/Services/OdbResultBatchRunner.cs` 及其检查保留作迁移对照；生产批量入口不再调用它。协议入口为 `/api/v1/odb-result-batches`，支持创建/列表/按 ID 查询及 `/cancel`、`/resume`；需本机 bearer 鉴权，不发送任意可执行步骤给后台。架构决策见 [ADR 0007](../submitter/adr/0007-durable-result-batches.md)。
