# 远端作业、完成确认与恢复（F008/F010）

WinUI 的「新建作业」通过已连接且已确认指纹的 Windows SSH 服务器提交；「作业概览」显示进度、日志与控制操作。输入选择上传本地文件或使用允许目录内的远端文件；请求包括作业名、INP、可选 oldjob/Fortran、CPU、内存及数据检查选项。完整入口与服务器配置见 [使用手册](../repowiki/user-guide.md)。

后台写入远端作业记录期间，「作业概览」保留最近一次读到的远端列表。本机作业及其日志可正常更新。后台写完后，页面在下一次定时读取时显示最新远端状态。手动刷新、暂停、恢复和终止仍向后台获取相应操作的完整结果。[作业概览](UI_INTERACTION.md#作业概览运行日志f005)

## 在资源页找到服务器

「全部资源」列出本机和已保存的服务器。「在线」显示已有本机采样的本机和已连接的远端。「未连接」只列已保存但尚未连接的远端。列表和侧栏使用同一筛选，上方统计卡仍显示总体情况。筛选隐藏所选节点时，详情清空，请重新选择操作对象。从服务器菜单显式刷新已连接主机时，工作台会显示对应节点。

添加和编辑服务器共用同一张表单。选择「SSH 私钥」后，可以直接输入本机路径，也可以点「选择文件…」选择带扩展名或无扩展名的文件。取消选择会保留原路径，选择器打开失败会在表单显示原因。保存配置时记录本机文件路径；密钥的读取和认证发生在连接服务器时。

## 已保存主机更换密钥

连接已保存的配置遇到新的 SSH 主机密钥时，先拒绝本次握手。请从服务器管理员或现场控制台取得新指纹，并在「计算资源 → 连接」的确认框中输入。页面同时列出原指纹与服务器本次提供的指纹，默认操作为取消。独立取得的值匹配后才允许再次验证。第二次握手仍需匹配该密钥并成功认证、读取资源，之后才保存新指纹。

核对仅对本次配置和本次观察到的密钥有效。取消、改连其他端点、认证失败、第二次握手密钥再次变化时，已保存的信任记录均保留。活动作业/传输的原服务器归属限制继续生效。旧后台返回一般连接错误时，界面显示拒绝原因，可升级后台后重新核验。刷新已断开的服务器会清空旧资源值，列表恢复为「未连接」，可重新连接。

## 读取连接状态与通信进度（F008）

资源页读取的是最近一次完整发布的连接/配置/资源快照。连接、目录读取、传输和远端脚本较慢时，状态读取不等待同一通信锁；快照带 `connection.busy` 和 `activity`，界面标示正在更新。有上一份资源值时明确显示“资源值为上次读取”；这些数值不是新采样，也不代表作业已完成。切换连接期间清空旧服务器资源，不能把旧机器数值显示为新机器数据。

已知忙状态下页面定时读取已有快照，不继续排入资源刷新命令；通信结束后读到最新状态并恢复原刷新方式。错误和指纹确认同样发布到快照，不能永久停留在“正在更新”。旧后台不返回新增字段时，客户端按原来的非忙状态显示。

界面收到连接或刷新失败后，再读取一次后台连接状态，避免错误条已出现而状态栏仍显示旧的已连接。若连后台状态也无法读取，资源视图显示连接异常、清除无法确认的资源值，并保留原始错误与状态读取错误；这只影响当前视图，不会断开服务器或将远端作业改为失败。

只有公开快照的读取使用独立的短锁；连接、上传/下载、身份核对和实际命令仍共用原连接锁。快照深拷贝，HTTP 层叠加受管作业数量或其他读取者改动返回值，不会反写服务内的资源数据。事件游标随完整快照发布，不单独跳到尚未发布状态的事件之后。测试 `tests/control_plane/test_remote_server_responsiveness.py` 覆盖阻塞通信中的真实 HTTP 读取、失败后复位、连接切换、文件操作和命令串行边界。

这项响应优化不等于已解决历史上远端作业 GET 的所有偶发超时；旧回归中的 5 秒超时仍保留其原验收边界，真实 SSH 与原生页面尚待验证。

## 完成证据

每次作业使用新建远端目录；启动时记录 launcher PID 和创建时间，后续不把重复使用的 PID 视为本作业。极快结束的 launcher 使用明确的已退出回执。每轮读 STA/LOG/DAT/MSG 各最多 80 行，并检查文件大小和修改时间；读取期间发生变化、目录/身份/文件不可读时不授权成功，显示“远端状态暂不可读，等待重新核对”。

正常分析接受既有成功分析标记；分析和数据检查都可接受严格匹配本次作业名的 `Abaqus JOB <name> COMPLETED` 整行。仅有输入处理器结束、进程消失或空日志不能证明数据检查成功。错误和终止标记基于共享常量，但数值奇异、零主元、过度畸变等诊断词本身不判失败，须明确错误前缀/失败摘要；也不把泛化的迭代 terminated 词当作整个作业终止。已经读到的明确错误/作业终止会保留，避免滚出尾部后变成成功。

有完成输出仍保持活动，直到 launcher 不活跃、锁文件不存在且四个输出的签名连续 3 次一致。轮询间隔 1 秒，调用与网络耗时另计。输出变化、进程重新出现或探测不可读会重置确认。确认后优先错误，其次本次取消请求/终止，最后成功。连续 5 次稳定无进程/锁却没有成功证据时，返回失败 `REMOTE_JOB_EXIT_UNCONFIRMED`，不会伪装成功。

## 日志、错误与取消

- 四种日志各自保存上一段尾部，按重叠行只追加新行；未变化时不重新追加整个尾部。最多保留 250 行，轮转或重写的无重叠内容作为新片段显示；不是完整远端日志归档。
- 错误输出对应 `ABAQUS_REMOTE_ERROR`，非本次请求导致的终止对应 `REMOTE_JOB_TERMINATED`；都需要先确认进程和文件已结束。
- 取消使用 Abaqus 温和终止，保持取消中直到稳定确认，不以“命令已发出”代替“作业已结束”。关闭仍复用受管任务检查，不因收到完成文本提前释放活动任务。

## 断线、重启与持久记录

每个新任务先将输入、阶段、取消意图及非秘密服务器身份写入控制面连接文件旁的 `remote-jobs.sqlite3`。沿用单后台持有锁和 SQLite 事务；记录不包含密码、私钥内容或口令。工作目录是 `<computeRoot>/<jobName>_<operationId>`，避免重试创建另一份作业。

启动前先持久保存 intent；服务器通过独占创建 `.abaqus-tools-launch.json` 认领本次启动，再写入 operation ID、launcher PID 和创建时间。重复启动请求只返回原回执。后台重启或启动响应丢失后只读取原回执、原目录和进程，不重发启动命令、不重新上传文件。已上传的本地输入即使移走，也不影响原任务跟踪或相同请求的查询；不同参数复用请求 ID 仍拒绝。

- **提交前中断**：尚处 preparing 的任务标记 `REMOTE_PREPARATION_INTERRUPTED`，不会自动重新提交。需要运行时，由用户明确发起新的请求。
- **提交后断线或重启**：任务保持活动，显示“等待重连核对”。在「计算资源」连接原服务器后自动核对；固定主机、端口、用户名、指纹、计算根目录、允许目录和 Abaqus 命令。其他服务器/范围拒绝接管。认证仍通过既有登录流程，不从任务记录恢复密码。
- **回执缺失或停在 starting**：显示“提交状态待核对”，保留活动状态；服务器可能在认领与启动/写回执之间退出，不能据此重新发起计算。需检查原目录、日志及实际进程；当前没有“强制认定未启动”入口。
- **身份/输出暂不可读**：显示“等待状态核对”，继续观察，禁用暂停/恢复。取消意图可保存，但在完整探测前不发控制命令。
- **离线取消**：先保存取消意图，重连后确认原任务仍活跃才发温和终止；已结束则直接做稳定确认。终止响应丢失不导致向已结束任务反复发送命令。
- **保存失败**：显示记录警告，继续观察已运行任务；禁止新提交和整体安全关闭，定时重试保存，不重试计算。新取消若保存失败，返回错误，不把未保存请求当已接受。
- **损坏或被其他后台占用的历史**：保留原文件，历史/新提交返回 `REMOTE_JOB_HISTORY_UNAVAILABLE`，不显示为空历史。应保留后台并检查磁盘、占用与原文件，不删除记录来绕过保护。

重要阶段立即保存，平稳轮询最多每 5 秒保存一次，避免每秒重写所有历史；每条任务独立更新。恢复日志重叠基线和明确错误/终止证据，但稳定次数从零重新核对。关闭界面不会隐式终止远端求解。设计理由见 [ADR 0012](../submitter/adr/0012-durable-remote-tracking.md)。

## 当前边界与后续迁移

上述进程判断覆盖本次 launcher，锁文件辅助判断异步求解；尚未完成远端全部 MPI/脱离 launcher 的子进程身份核对。没有声称独立并发负载或真实 SSH/Abaqus 验收已经完成。

仅从本功能版本开始提交的任务有持久记录；升级前只存在旧后台内存中的远端任务无法自动重建。独立文件传输仍采用原来的生命周期，不承诺跨后台恢复。实际 SSH、凭据重输、WinUI 点击和远端 MPI 尚待验收，不能因为本机进程恢复通过就宣布 F010 或全迁移整体完成。

2026-11-19已对用户提供的192.168.1.202完成SSH握手：端口22可达，主机指纹与已有“计算节点01”配置一致。回执`GPTWork/ssh-readonly-probe-20261119.json`明确`authenticated=false`；只说明网络和服务器身份核对通过，不代表登录、目录读取、传输或远端作业通过。随后用户已在隔离窗口登录，原生资源和目录浏览/上传实际通过；下载发现Windows同步错误，正在修复并重验，见[远端传输](REMOTE_TRANSFERS.md)。最初握手回执仍保留其未认证的当时状态，不将密码写入文档或测试夹具。

## 提交按钮未收到回执时

WinUI 在第一次提交前，将请求编号、作业参数和当时连接的服务器身份保存在当前配置目录的 `pending-remote-job.json`。写入失败会提示本次未发送。记录不包含登录口令、私钥或私钥口令。每个配置同一时间保留一项待核对的远端提交。

网络断开或后台响应超时后，点击「核对上次远端提交」查看原作业。切换页面、编辑表单或重开应用都可以继续核对；在本机模式也能从待核对提示进入。已登记的作业直接显示原回执。若后台尚未登记，可选「按原参数重试」、 「放弃未登记请求」或「返回」。重试必须连接原服务器；放弃会在后台记住请求编号，迟到的同一请求随后也不会启动作业。若受理与放弃同时到达，以后台先登记的结果为准。「放弃未登记请求」不会停止已经受理的作业，也不会向作业概览添加一条虚假的完成记录。

如果后台无法确认历史记录，待核对编号会保留。如果已确认回执但本机无法清除记录，页面会说明已确认的作业状态；修复写入后再次核对即可。旧版客户端在此次改动前产生且没有保存编号的超时提交，仍需从作业概览核对。

- 业务入口：`modules/control_plane/remote_jobs.py` / `RemoteJobOperationManager`，启动/状态 PowerShell 由 `_start_job_script`、`_job_status_script` 生成。
- 确认算法：`modules/control_plane/remote_job_monitoring.py` / `RemoteCompletionState.observe`、`new_tail_lines`。
