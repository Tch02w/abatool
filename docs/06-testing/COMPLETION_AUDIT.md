## 历史库与后台启动失败

11 月 28 日在 G 盘隔离目录内以当前工作树运行 `tests/control_plane/test_operation_journal.py`、`tests/submitter/test_scheduler_repository.py` 以及 `tests/control_plane/test_api.py` 中的 `test_failed_startup_releases_services_and_allows_retry`。共 12 项通过，回执为 `GPTWork/storage-audit-docs-20261128-48a6d46e/regression.xml`。[存储和恢复约定](../03-features/LOCAL_SCHEDULING.md#已有调度库首次建库和后台启动失败)

| 情形 | 已核对的结果 |
|---|---|
| 操作历史首次建库出错 | SQLite 拒绝写入版本后，正式路径仍为空缺。解除故障后成功建库，保存的记录可在重开后读回。若原本已有零字节的文件，则报告错误，保留其内容。 |
| 打开既有调度库 | 写事务期间另一连接可读取已提交的作业和事件。独占锁会报告占用，解锁后可读回原记录。版本 2 的样例被拒绝，文件 SHA-256 与打开前相同。大小写混合的列与同名触发器可正常读取。损坏文件和已知表结构不兼容仍有备份重建检查。 |
| 后台初始化失败 | 在本机调度器构造及连接信息发布两处分别注入错误。旧连接信息保留，已启动的通知维护线程结束。同一配置重新启动后，作业通知接口返回 HTTP 200。 |

这组检查覆盖可控启动异常和 SQLite 并发读写。突然断电、整机重启后的磁盘持久性及整套运行中的间歇超时，仍需各自的验收证据。
