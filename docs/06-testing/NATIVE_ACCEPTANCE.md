# WinUI 原生业务验收步骤

本表执行[迁移合同](../winui-migration.md)中的实际交互要求；实现、接口和控件测试的证据见[交付核对](COMPLETION_AUDIT.md)。本表不是通过证明。每项需在任务记录中保存所用版本、独立配置、实际步骤、观察结果和未验分支；只读到窗口文字不证明鼠标、拖选或视觉布局正常。

## 测试准备与记录

使用[当前候选](../08-handoff/CURRENT_STATUS.md)及G盘独立配置，所有测试副本、临时目录、导出和回执留在GPTWork。G:\Job原始INP/ODB只读，不能将ODB放到C盘。不能对归属未知的计算使用终止、重新排队或清理。

当前可继续使用的窗口和准确进程身份在[TASK-001](../08-handoff/ACTIVE_TASKS/TASK-001-postprocessing.md)顶部。队列候选是只有Heading的界面夹具，不是可计算模型：不得点击开始队列或把它当求解样本。真实执行、连续重启动及SSH既有回执保持原证据范围；需要新的执行验收时先核对专用数据与授权，不能用界面夹具代替工程模型。

记录统一使用四种结论：通过、失败、受阻、未执行。写清是用户实际操作、桌面工具操作、无障碍文字观察还是后台/文件检查。用户确认与工具结果不一致时保留两者，不能覆盖失败记录。每次只保留一个当前待反馈问题；反馈后继续下一步骤，不反复打开相同版本或重复登录。

## 结果浏览当前步骤

1. 在左侧「模型甲」中选择load_point_raw.csv，核对表格中的荷载123。输入框路径末尾由「当前结果」改为「待读取结果」，暂不点击读取。表格应仍为123，提示显示尚未读取和实际操作目录「当前结果」。
2. 保持此状态点击刷新索引，待完成后核对仍为123，输入框仍是「待读取结果」。侧栏刷新和「内部」选项切换也不应提交新目录。
3. 通过「更多 → 导出所选」选择本次独立的export-acceptance目录，核对完成提示及实际导出内容为123。两份同名源文件应分别保持123和999。目录和文件摘要由验收方核对，不要求用户手工计算。
4. 点击「读取目录」，重新选择模型与CSV，应变为999、待读取提示消失。输入不存在的目录并读取，应明确报错、清空旧结果，不留下可对旧文件执行的按钮。
5. 恢复合法目录，分类切为「全部」后选result.xlsx，核对首工作表、中文及空单元格。宽表数据需另用已有24列样本；逐组切列和复制应保留本次预览的所有列。
6. 分页需使用超过500条的专用结果目录，检查下一页/上一页、输入未提交搜索时的翻页、重新筛选回第一页。两条记录的当前夹具不能证明分页通过。
7. 大文件导出取消、部分失败和关闭等待另用可重复的专用数据。取消后只保留已完成项，未完成项不能显示为成功；关闭超时应返回应用。回收站只操作明确可丢弃的导出副本，并核对确认与还原后重建索引，不操作源ODB。

## 共用窗口、菜单与关闭

| 范围 | 实际检查 | 通过条件 |
|---|---|---|
| 布局 | 深浅主题、最小尺寸、侧栏展开/收起、不同DPI显示器 | 标题/控件对齐，无裁切/遮挡，最小宽度限制有效，状态栏可读 |
| 参数帮助 | 悬停问号，移入提示区，再移出；键盘访问 | 小图标与输入排列一致，移入不消失、移出关闭，无“知道了”按钮 |
| 顶部导航和菜单 | 八页逐次切换、四组菜单逐项核对，Ctrl+7/8 | 导航和菜单作用于同一当前对象；空白区域不出现裸快捷键提示；切页不取消后台任务 |
| 草稿/关闭 | 空闲关闭、活动模拟任务取消关闭/后台继续/重开/停止并关闭均已实测；另验保存失败和超时 | 恢复原后台与原执行记录，失败时保留可用界面，不误停其他任务 |
| 无开发环境目标机 | 在未安装Python/.NET SDK的目标Windows运行目录包/安装程序 | 正式程序、后台和各项业务能运行；本机打包或依赖探针不能替代该检查 |

未准备目标机、真实远端环境或必要测试数据时写“受阻/未执行”，不能以等效模拟直接标为通过。准确进度仍以[任务索引](../08-handoff/TASK_INDEX.md)和[交付核对](COMPLETION_AUDIT.md)为准。
