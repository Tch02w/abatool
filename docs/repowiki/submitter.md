# 作业提交与调度

## 本机工作流

```text
作业草稿 → 后端校验与命令预览 → 候选区 → 正式队列
        → 资源分配 → Abaqus 进程 → 运行证据 → 完成/失败/终止
```

正式队列是唯一调度入口。队列操作由 `modules/control_plane/job_queue_commands.py` 执行，运行循环由 `local_queue_runtime.py` 管理，实际进程启动与停止位于 `modules/submitter/local_job_execution.py`。界面刷新只读取快照，不直接改变调度状态。

原生控制面通过 `local_scheduling.py` 复用 `SchedulerCore` 和 SQLite 记录，按优先级、资源、依赖与目录冲突分配，保存执行身份后再启动。状态未知先扫描，不重复执行；结果保存失败只重试保存。百分比内存、自有 RSS 和原生验收限制详见 [F004/F005 本机调度](../03-features/LOCAL_SCHEDULING.md)。

## 重启动与结果

Restart 作业通过 `oldjobPath` 和依赖 job ID 建链。`restart_chains.py` 计算阶段、循环、缺失父作业和路径兼容性；原生页面可编辑依赖并定位正式队列条目。

原生重启动页面以节点图显示计算关系：每个 Restart 节点最多一个父节点，一个父节点可以产生多个分支。计算图不显示 ODB 合并节点。用户可从任一有效 Restart 节点创建“完整结果计划”，控制面只解析该节点唯一的祖先路径，兄弟分支不会进入计划。

同名结果策略支持备份、覆盖或取消。工作目录准备、SSD 临时目录、结果归档和中断清理由执行层集中处理，不允许页面自行移动求解文件。

## 远程能力

服务器配置、指纹确认、资源刷新和 SSH 生命周期由 `remote_servers.py` 管理；文件传输和远程作业分别使用独立异步操作管理器。允许访问的远端根目录由配置约束，所有路径在执行前再次验证。

远端完成需成功输出和进程/锁/文件稳定的共同证据；数据检查、错误优先、日志增量及未完成的连接中断/后台重启恢复见 [F010 说明](../03-features/REMOTE_JOBS.md)。不要把传输或 SSH 异常导致的操作失败当作远端求解已经退出。
