# ADR 0010：原生控制面复用本机调度核心

- 日期：2026-11-18
- 状态：已实现，原生业务与真实负载验收待完成
- 范围：F004/F005；补充 [ADR 0001](0001-local-control-plane-scheduling.md)，不替代关闭协议

## 问题

PySide 提交器已经使用 `SchedulerCore`，原生控制面仍按队列顺序和并行上限直接派发，未执行同一套优先级、总资源和目录冲突规则，也未保存可用于重启核对的执行批次身份。

## 决策

通过 Qt-free `LocalQueueScheduling` 将正式队列投影到现有核心，复用 `SQLiteSchedulerRepository`。运行管理器持有锁协调计划、保存和线程启动。启动前完成 JSON 与 SQLite 写入；状态未知保留、观察且不重放；缺失 JSON 的活动记录由调度库重建观察条目。完成结果保存可重试，求解本身不能因保存失败被重复执行。

合计 CPU 预算采用逻辑线程，单作业上限保持按 Abaqus 版本区分；绝对内存扣除申请量未体现在 RSS 的部分，百分比不假装是实际需求。详细口径和限制见 [本机调度说明](../../03-features/LOCAL_SCHEDULING.md)。

## 影响与限制

WinUI 增加调度原因显示，使用现有队列操作入口。JSON/SQLite 不具备共同原子提交，中断后以待核对状态防止重放。重启观察不等同于接管进程，不能根据 PID 名称终止外部作业。停止/关闭仍由 [ADR 0009](0009-reversible-workbench-close.md) 协调。

不引入 Qt、许可证配置或跨节点调度；不删除旧 UI。动态内存学习、持续自有作业 RSS 上报、真实资源负载和原生页验收仍需继续，不能据本轮检查宣布完整迁移。
