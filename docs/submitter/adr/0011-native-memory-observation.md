# ADR 0011：原生内存观测、共享扫描与有来源的估计

- 日期：2026-11-18
- 状态：已实现，真实 Abaqus 负载与原生交互待验收
- 范围：F005/F007；补充 [ADR 0010](0010-native-shared-local-scheduler.md)

## 原因

原生调度未持续接收自有作业 RSS，绝对内存可能重复预留；旧内存学习服务未接入，按 job name 的旧估计映射还可能混合同名不同目录的作业。

## 决策

Qt-free 执行器共用带锁的进程快照，核对启动时间、PID 和工作目录身份，持续回报可读/不可读状态；批量保存并保留短峰值。控制面复用旧纯 Python 学习器，以作业 ID 投影资源，以模型文件元信息和执行选项区分历史。历史存入调度库兼容的附加元信息，错误不触发求解重放。

系统可用内存已包含实际占用，预留只补齐需求与新鲜 RSS 的差；沿用 85% 可用内存与 1.10 峰值余量。当前实测、同模型历史和其他作业参考在界面分开。具体算法、冷启动、include 元信息限制、错误与取消见 [内存观测说明](../../03-features/MEMORY_MONITORING.md)。

## 边界

不把百分比配置当作实际预留，不从进程名称推断终止权，不把采样失败变成零占用；不保证未经历步骤的峰值。旧 PySide 界面及适配器保留。真实 Windows 测试 helper 只能证明进程采样和持久恢复链路，不能替代真实 Abaqus/MPI 高负载或原生页面验收。
