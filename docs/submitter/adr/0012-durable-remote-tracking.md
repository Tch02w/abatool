# ADR 0012：远端任务持久跟踪与不重复启动

状态：已实现，2026-11-18。关联 F008/F010。

## 问题

远端计算的寿命长于 SSH 连接和本机后台。原来的进程内任务表会在后台重启后丢失，SSH 错误也不能证明远端计算停止。直接重试提交会在服务器启动第二份计算。

## 决策

复用 `OperationJournal` 的独占持有锁和 SQLite 事务，以 `remote-jobs.sqlite3` 保存请求、固定服务器身份、阶段、取消意图、明确错误证据及日志尾部。保存失败时不启动新计算、不授权整体关闭；损坏记录不当空表。

启动前保存 intent，服务器以独占文件创建认领启动，原子替换为包含 operation ID、PID 和创建时间的回执。恢复只读原回执并观察原作业；不调用启动和上传流程。原服务器身份、指纹及路径范围必须匹配，核对和实际操作共用连接锁。认证秘密不写任务记录。

回执缺失/不完整无法证明没启动，保留未确认活动状态。此方案提供应用重试下的单次启动约束，不声称服务器文件系统故障下的分布式事务；认领与进程启动之间仍有不能自动判定的窗口。接受这一限制，优于在不确定状态自动重复计算。

## 影响与验证

公共 DTO 仅新增可选跟踪状态和持久警告。原生界面区分重连、提交未知、状态不可读；未核对时暂停/恢复禁用。离线取消先落盘，确认原任务活动后才发温和终止。稳定确认计数恢复时重置。

既有终态和旧 DTO 兼容；升级前无持久记录的任务不能凭空恢复，独立文件传输持久化不在本 ADR 内。自动化覆盖替身 SSH、真实本机 PowerShell 和两个后台进程间恢复；实际 SSH、MPI 和原生业务操作仍待验收。入口与证据见 [远端说明](../../03-features/REMOTE_JOBS.md) 和 [TASK-002](../../08-handoff/ACTIVE_TASKS/TASK-002-migration.md)。
