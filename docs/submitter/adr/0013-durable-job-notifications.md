# ADR 0013：持久作业结束提醒

状态：已实现，源码/正式客户端验证通过；完整包及原生交互验收分别记录在 TASK-002。

## 问题

原生新建作业已经保存“结束提醒”，却没有展示入口。仅在页面轮询时提示会遗漏关闭界面期间的结束事件；每条消息打开模态窗口会打断批量操作。重新运行同名作业也不能覆盖旧执行的提醒身份。

## 决策

控制面在本机与远端确认终态时写入独立 SQLite 提醒日志。复用 OperationJournal 的单持有者锁、事务和校验，增加可选顶层 ID 字段，保持现有合并/批次/远端日志格式不变。来源与执行 ID 生成稳定提醒 ID；已读记录保留用于去重。后台重启按存储起点补查作业终态，不补发升级前所有历史。

提醒完成写入后才能确认已读。写入失败保留内存并重试，待保存提醒参与共同关闭检查；不因通知失败重新执行作业。联合锁顺序为作业管理器在前、提醒管理器在后；历史补查在不持有提醒锁时读取作业管理器，避免反向锁顺序。持久化起点、记录损坏和磁盘失效均不能伪装为空历史。

WinUI 使用全局非模态提醒区和可重新打开的菜单入口，显示最多 50 条。轮询相同记录不重建列表；弹层阅读时冻结当前列表，批量已读仅针对屏幕中实际显示的 ID。查看作业验证执行身份，找不到原执行就保留目录供核对，不误跳新一轮作业。

## 取舍与证据

当前不依赖 Windows 系统通知中心。界面关闭后由后台保存提醒，下次打开再展示。强制退出且磁盘持续不可写、原作业历史又被删除时，无法保证恢复未落盘的提醒。已读历史不自动删除，长期存储维护另行设计，不擅自清理用户记录。
