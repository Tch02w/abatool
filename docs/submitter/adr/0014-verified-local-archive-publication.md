# 0014：本机归档先校验发布，再清理源文件

日期：2026-11-18。状态：已实现发布保护、持久归档恢复和独立重试；原生及跨卷负载待验收。

旧原生执行器以 shutil.move 逐文件/跨卷移动，失败可能拆散 Restart 文件族；目录创建异常还可能掩盖已经确认的求解完成。用户要求继续完整迁移，并在行为改动前说明优于原实现的方案，本次已先说明复制校验和独立归档结果。

决策：WinUI 本机执行器调用 Qt-free `local_archive`；归档根目录内暂存完整副本，分块计算源 SHA256 并重读目标验证，写入带执行身份的清单，最后同卷目录 rename 发布。可选清理发生在发布后，仅处理已登记且再次核对的文件，不递归删除未知内容。清理关闭时改为保留源文件。锁/目录链接/原始输入冲突拒绝，空归档不能报成功。

求解状态独立于归档状态；归档失败、取消、清理未完成或完整性待核对均公开显示并持久保存。旧失败目的地不能用于依赖或默认输出定位，新执行不得沿用上一次归档字段。Qt 旧入口保留，远端归档不在本次变更范围。

恢复决策：原求解完成证据和归档阶段按 itemId/attemptId 持久保存，原子替换检查点，原生文件锁覆盖整个操作。重启仅展示待恢复，用户从作业概览显式恢复；复用核对通过的副本，保留未完成副本现场，发布后核对全清单再续清理。归档占用运行/关闭保护和重叠目录，独立路径不进入求解器启动与计算资源样本记录。损坏或执行身份不符记录不能把未知求解改为成功。

取舍：额外磁盘空间及完整摘要读写成本，换取复制失败时源文件保留和明确发布边界。并非全目录排他锁或断电级事务；原生锁防止同次归档重复接管，不排除外部软件写文件。保留临时目录和完整发布清单作为核对证据，不自动删除历史。独立归档提醒尚未写入前的崩溃不保证补发，归档状态自身可以恢复。
