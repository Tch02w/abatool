# ADR 0021：结果导出的完整文件发布与关闭等待

状态：已实现并通过独立文件/相关回归；原生交互待验。关联F001/F021。

## 问题

原WinUI导出调用逐文件CopyAsync，未标记忙碌或登记关闭等待；用户重复点击或关闭时可能与复制冲突，部分失败只显示通用错误。目录索引也不能将尚未完成的导出副本当作结果。

## 决定

由独立ResultFileExport服务捕获选择快照，在后台线程使用1MiB缓冲和异步流复制。进度按文件字节更新，最多约每100毫秒一次，首块和完成单独报告；界面显示完成数量、当前文件和取消按钮，结果记录列出实际目的路径与未完成源路径。

保留相对目录与重名避让；仅从当前结果根目录下导出文件，拒绝链接路径，非法展示相对路径回退原文件名。用只读共享打开源，核对大小与修改时间；复制到本次独有`.abatool-export-*.part`，刷新并关闭后以不覆盖方式改为最终名称。索引已有`.part`排除，实时目录追加相同前缀排除。取消/失败停止后续文件，保留已完成项，只移除本次拥有的临时副本；清理失败报告保留路径，不伪装为整批成功。

导出从目录选择器打开前就登记PendingResultFileOperation，回收操作同样从确认框前登记。两个操作互斥，关闭等待整个流程；30秒仍未结束则取消关闭并提示返回取消导出。取消文件选择或关闭已开始时不再启动复制。不因取消关闭而自动取消一个已有导出。

## 边界

这是前台文件操作，不转移到后台控制面；关闭后的后台继续模式不包含仍在复制的导出。结果记录目前保留在当前页面，未建立跨重启导出历史。异常断电/进程终止可能留下不发布的`.part`，没有自动续传；不清理其他操作的副本。应用运行于Windows，源共享保护与发布冲突以实际文件系统为准，不能据本机测试宣称网络文件系统和原生交互全部通过。测试仅G:隔离结果文件，没有移动用户ODB。
