# ADR 0023 · 后处理分组的排队、取消与恢复

## 背景

PySide 允许在一个对比组运行期间追加其他组。它在组轮到执行时读取成员、参数及图例；取消当前组后，等待工作线程结束才处理下一组。最初的 WinUI 会一次提交整份计划并锁定页面，关闭前台也会失去修改后续顺序和停止范围的入口。

## 决定

分组队列由 Qt-free Python 控制面持有。同一工作区内，命名组按组名识别，独立模型按 ODB 完整路径识别；每次实际入队另有唯一条目标识。追加时忽略正在运行或仍在等待的同组。开始执行前核对来源，使用后台最后接受的等待组配置，沿用原有提取、组内云图统一范围、缓存及发布流程。

每次编辑、取消或清空操作携带命令标识与所见队列版本。取消当前组还要匹配该条目标识，避免网络重试或队列刚好前进时停错作业。后台先记录提交意向，再派发该组。单组完成、失败或取消均保留记录；成功发布的文件可单独打开。整批停止还要清除等待项。

队列记录位于隔离工作区运行目录的 SQLite 中，与前台显示及工作区草稿分开。前台重开应接回同一队列。后台重启时，曾进入执行的条目可能仍有外部进程或不完整产物，须核对该次提交的发布记录和源文件后再继续。状态不明的条目不能由前台自动重试。服务关闭按组队列、子操作的顺序协调，保证工作线程实际退出后才报告可停止。

## 影响与验证

既有整批运行、结构读取、通用对象提取接口继续可用。新路由是 `/api/v1/odb-postprocess-group-queues`。首次读取队列或手动核实时请求完整状态；定时查询携带 `afterVersion`，版本保持时响应的 `operation` 为空，当前子任务的进度仍由原接口提供。分组队列的幂等性、版本冲突和中断恢复由独立接口测试覆盖，真实模型的分量与图例仍用原提取器核验。原生操作和验收范围见 [TASK-001](../../08-handoff/ACTIVE_TASKS/TASK-001-postprocessing.md)。
