# WinUI 3 前端迁移合同

## 当前实现快照（2026-08-31）

八个原生页面、四组菜单、本机控制面、ODB 发现与兼容性、结果索引与预览、ODB 合并、完整后处理批处理、本机队列、远程服务器/文件/作业以及重启动链均已接入。当前剩余发布门槛是全量回归、Release 打包、真实 Abaqus/SSH 烟测和隐私审计；PySide6 兼容入口在完成发布评审前继续保留。

根据原生界面验收反馈，壳层采用紧凑自定义标题栏和页面自治布局：各页面直接拥有自己的上下文、进度、日志与操作区，不再显示重复且无真实状态源的全局静态项目栏、属性栏和底部 TabView。

## 1. 目标、范围与停止条件

本迁移只替换桌面前端及其进程间适配层，不重写已验证的 Abaqus、调度、SSH、ODB 和结果索引领域逻辑。WinUI 3 版必须在同一窗口内达到现有 PySide6 版的功能、状态恢复、错误处理和关闭安全性对等；视觉可以采用 WinUI 3 原生交互，但不得删减业务能力。

在第 7 阶段全部验收通过前，**PySide6 实现、依赖、入口和旧数据兼容代码必须保留且可运行**，不得以占位页或 WinUI 3 已能启动为由删除。默认入口的切换与 PySide6 退役是单独决策，不属于中间阶段的完成条件。

优先级：P0 为阻断发布的业务或数据安全能力；P1 为日常完整工作流；P2 为便利性和视觉对等。每一阶段必须同时满足功能测试、失败路径测试和重启恢复测试，才可进入下一阶段。

## 2. 固定信息架构

主导航固定为以下 8 页，名称和顺序是兼容合同；不得合并、改名或只保留跳转占位。

| 顺序 | 页面 | 优先级 | PySide6 事实源 | WinUI 3 功能对等验收 |
|---:|---|---|---|---|
| 1 | 新建作业 | P0 | `modules/submitter/workbench_ui.py`、`modules/submitter/main.py`、`modules/submitter/cluster_ui.py` | 可选择 INP/Fortran/旧作业文件，配置作业名、计算与归档路径、CPU/GPU/内存、精度、优先级、交互/数据检查/通知和本地/远程参数；校验、命令预览、提交、错误定位与配置保存均真实工作。不得继续依赖“隐藏且未显示的 SubmissionWizardDialog”传值，须由共享 Draft/DTO 驱动。 |
| 2 | 作业队列 | P0 | `modules/submitter/queue_manager.py`、`modules/submitter/scheduler.py` | 候选扫描、加入/移除、排序、并行上限、开始/停止队列、依赖与重启动编辑、资源参数编辑、持久化及异常恢复对等；正在运行的作业不可因刷新或重启丢失。 |
| 3 | 作业概览 | P0 | `modules/submitter/main.py` | 显示排队、运行、暂停、成功、失败、取消和外部恢复作业；日志、进度/耗时、工作目录和输出结果可追踪；选择作业后属性与操作同步更新。 |
| 4 | 计算资源 | P1 | `modules/submitter/workbench_ui.py`、`modules/submitter/server_ui.py` | 本机 CPU/内存/STA/作业数持续刷新；SSH 连接、主机指纹确认、断开与远程资源刷新可用。现版未实现的远程作业控制继续明确禁用，不伪造成功。 |
| 5 | 重启动链 | P1 | `modules/submitter/main.py`、`modules/submitter/queue_manager.py` | 创建、编辑和显示 oldjob 依赖链；校验循环、缺失父作业和不兼容路径；提交顺序、状态传播及持久化对等。 |
| 6 | ODB 合并 | P1 | `modules/submitter/workbench_ui.py`、`modules/submitter/main.py` | 选择原始/重启动 ODB，配置历史输出、压缩、保留原文件、命名与冲突策略；兼容性检查、进度、停止、失败清理及结果打开对等。 |
| 7 | ODB 后处理 | P1 | `modules/postprocessor/app.py`、`main_window.py`、`safe_defaults.py`、`comparison_groups.py`、`batch_window.py`、`group_ui.py` | ODB 扫描、版本检查/升级、19 列任务表、分组/对比组、图例范围、批处理队列、停止/重试、产物定位和关闭保护对等；现有四层继承与 monkey patch 的行为先通过服务接口固化，再迁移界面。 |
| 8 | 结果浏览 | P1 | `modules/postprocessor/result_browser.py`、`result_browser_page.py` | 结果索引构建/刷新/恢复、树与表筛选、预览、打开/定位/删除前确认及索引错误提示对等；大目录索引不得阻塞 UI。 |

壳层固定行为：八个页面共享紧凑标题栏、菜单、顶部导航和底部状态栏。页面内部自行显示与其真实状态源绑定的上下文、属性、日志和操作区；不得恢复无数据绑定的全局静态侧栏或重复 TabView。页切换不得取消后台任务或丢失选择。

## 3. 菜单、状态栏与窗口协议

### 菜单

| 菜单 | 固定命令 | 验收要求 |
|---|---|---|
| 文件 | 新建作业、退出 | 新建作业切到第 1 页并重置/确认未保存草稿；退出必须走统一关闭协议。 |
| 作业 | 管理队列、开始队列、终止队列 | 与第 2 页同一命令源和 CanExecute 状态，不得出现菜单与页面状态分叉。 |
| 服务器 | 连接/配置、刷新、断开 | 与资源页共享连接状态；未连接时刷新/断开禁用；主机指纹变化必须再次确认。 |
| 后处理 | 当前作业转到后处理、打开 ODB 后处理、打开结果浏览 | 保留 `Ctrl+7` 和 `Ctrl+8`；“当前作业”须通过路径路由解析候选 ODB，失败时给出可操作原因。 |

### 状态栏

状态栏至少包含：当前短消息、后台忙闲/进度、本机 STA 与内存摘要、远程连接状态、当前运行时标识。所有值来自同一状态存储；忙操作结束、失败或取消后必须复位。WinUI 3 版运行时标识显示 `WinUI 3`，不得硬编码旧的 `PySide6`。错误详情进入日志，状态栏保留可读摘要。

### 关闭协议（P0）

`Window.Closing` 必须取得异步 deferral，并按以下顺序执行：

1. 请求结果浏览器停止索引/预览并确认无未完成的破坏性写入；
2. 请求 ODB 后处理器停止或保留批处理，处理未保存分组与升级/合并临时文件；
3. 请求提交器保存草稿、队列、调度器与窗口状态；运行中作业必须让用户选择继续后台、温和停止或取消关闭，禁止默认强杀；
4. 停止轮询、SSH、文件监视和桥接事件订阅，等待有界超时；
5. 原子写入持久化状态，确认无孤儿工作进程后才关闭桥接进程和窗口。

任一子系统拒绝、保存失败或用户取消，整个关闭必须取消并保持可操作状态。重复点击关闭须复用同一个关闭任务，不能并发执行两次。

## 4. WinUI 3 与后台的稳定边界

WinUI 3 页面只依赖 ViewModel 和带版本的 DTO，不得直接操作 Python 对象、SQLite 行、Paramiko 会话、Abaqus 子进程或解析器内部状态。既有 Python 领域代码先作为后台服务保留，通过可测试的命令/事件边界调用；协议应支持取消、关联 ID、进度、结构化错误和超时。

最小命令族：配置加载/保存，路径与提交校验，命令预览，本地/远程提交，队列增删改/启停，作业暂停/恢复/温和停止/强制终止，服务器连接/刷新/断开，重启动链校验，ODB 兼容性检查/升级/合并，后处理分组与批处理，结果索引/预览，以及 Prepare/Commit/Abort Shutdown。

最小事件族：资源快照、连接状态、队列快照、作业状态/日志、长任务进度、索引状态、结果变更、用户确认请求和结构化错误。事件统一携带 `aggregateType`、`aggregateId`、时间戳和单调序号；`aggregateId` 按事件类型对应 operation ID 或 job ID，重试执行另带 `attemptId`。UI 线程只渲染最新状态，过期事件不得覆盖新状态。

数据兼容合同：继续读取现有设置、作业列表、调度数据库、项目状态和结果索引；写入使用原子替换并可由旧版读取，若必须升级格式则先备份、记录 schema 版本并提供回滚。中文、空格、长路径、网络路径和 Abaqus 非零退出码均为必测输入。跨模块只传 DTO/路径，不允许提交器和后处理器互相引用 UI 类型。

## 5. 分阶段执行与验收清单

### 阶段 0：基线冻结与桥接契约（P0）

- [ ] 记录 8 页、菜单、状态栏、对话框和关闭行为的 PySide6 基线；固定测试样例与持久化样本。
- [ ] 建立可启动、可打包的 WinUI 3 壳及 ViewModel/DTO 层，8 页导航名称与顺序一次固定。
- [ ] 定义命令/事件 schema、版本协商、取消、超时、日志脱敏和后台失联恢复；提供假后台契约测试。
- [ ] PySide6 入口仍可独立启动并通过现有测试。

### 阶段 1：当前第一纵向切片——ODB 发现与只读兼容性检查（P1）

第一片优先验证 WinUI、Python 3.14 控制面和 Abaqus Python 3.10 三层边界，且只读源 ODB，避免在协议尚未稳定时触及求解队列或破坏性文件操作。

- [ ] WinUI 3 壳可启动并固定 8 页导航；第 7 页可选择/输入目录、递归发现 ODB，并展示路径、大小和修改时间。
- [ ] 控制面只绑定 `127.0.0.1`，使用随机端口、实例描述文件和 bearer token；命令使用版本化 JSON，事件带全局单调序号并可断线重放。
- [ ] 发现规则与 PySide6 一致：排除结果目录、`.git`、`.venv`、`-old` 和升级临时文件，支持中文、空格和自然排序。
- [ ] 选中 ODB 后可创建异步兼容性检查，调用现有 Abaqus 3.10 worker，逐文件呈现 `valid / upgrade_required / newer_release / invalid / missing / empty`、进度和结构化错误。
- [ ] 支持取消、UI 重启后重连和重复命令幂等；控制面或 worker 异常退出时不发布半成品，也不修改源 ODB。

切片验收门槛：相同目录经 PySide6 与 WinUI 3 得到相同的 ODB 顺序与兼容状态；API 契约测试、Python 测试、WinUI 构建和 Windows 原生启动烟测均通过。兼容性检查完成前，静态占位页不得被描述为已经迁移。

## 6. 完成定义

“页面已画出”“命令已接线”或“单次演示成功”均不算完成。某项只有在真实后台、取消/失败路径、持久化重启、可访问的用户反馈和自动化/手工证据齐全时才能勾选。发现 PySide6 行为含糊时，先以现有数据安全语义为准并补契约测试；不得在 WinUI 3 中静默改变规则。
